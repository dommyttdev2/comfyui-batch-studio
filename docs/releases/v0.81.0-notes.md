## v0.81.0 — 標準ComfyUIノードによる画像単位実行

Comfy Batch Studioの画像生成から、ComfyUI-Scene-Prompt-Toolsと
comfyui_anima_batch_orchestratorへの依存を完全に削除しました。
Local・Remote Workerの両方で、追加custom_nodesを導入せずに生成できます。

### 変更内容

- 1 Leaf = 1 POST /prompt = 1 imageとして、Prompt PlanのBranch・Leaf順に実行します。
- 共通LoRAとBranch LoRAを標準LoraLoaderで順番に適用します。0件・複数件とMODEL／CLIPの独立した強度指定に対応します。
- 共通・Branch・画像ごとのpositive／negativeをBatch Studioが合成し、標準CLIPTextEncodeへ渡します。
- IllustriousはCheckpointLoaderSimple、AnimaはUNETLoader／CLIPLoader／VAELoaderを使用し、KSampler → VAEDecode → SaveImageで生成します。
- 画像ごとのseedとWorkflowをRun作成時に固定します。Resumeは同じ入力を再利用し、受理状況が不明な送信の自動再送を防ぎます。
- Historyを正本として画像を回収し、Branch／Leaf／prompt ID、サイズ、SHA-256を記録します。PNGには画像単位のWorkflow metadataを渡します。
- custom-node repository設定・Remote同期処理・旧Scene実行クライアントと独自API呼び出しを削除しました。

### 付番と互換性

`0.80.0` → `0.81.0`（MINOR）。旧生成Workflow・Template・Manifest・Runの実行契約を廃止する非互換変更のため、プロジェクトの付番ルールに従って機能版を上げます。

開発段階の`0.x.y`リリースです。旧方式へのfallbackや実行互換アダプタはありません。
旧Workflow・Runをそのまま実行・Resumeすることはできません。
保存済みプロジェクトや画像、利用者のComfyUIに導入済みのcustom_nodesを自動削除する処理はありません。
Compiler／Templateは3、Manifest schemaは2、Remote Worker protocolは12です。これらはアプリ番号とは独立した契約番号です。

### 更新・移行手順

1. 実行中のRunを終了させます。送信結果が不明なpromptは、更新前にComfyUIのQueue／Historyと保存済みprompt IDを照合してください。確認できるまで同じ画像の置き換え生成を開始しないでください。
2. Batch Studioを終了し、`update.bat`で最新正式リリースへ更新します。`run.bat`で依存関係の更新・ビルド・起動を行います。
3. プロジェクトのモデル選択とPrompt Planを確認し、Workflowを再生成します。独自Template／Manifestを指定していた場合は、内蔵の標準Templateへ切り替えてください。
4. Preflightを確認し、新しいRunを作成して生成を開始します。旧Runを再開する操作では移行できません。

### 検証と範囲

- 全リポジトリ回帰テスト、型チェック、整形・Lint、隔離コピーでの通常ビルドを検証しています。Lintには既存の未使用変数警告があります。
- 追加custom_nodesを無効にした実ComfyUIで、Illustrious／AnimaのCompiler → seeded Run → Local生成 → 画像検証が成功しました。
- Linux Remote Workerでも両モデル系統の実生成、History照合、ZIP／manifest作成が成功しました。検証用HTTP中継を使用し、Workerの生成処理は変更していません。
- LoRA接続順・強度、停止／中断／Resume、不確実な送信の復旧、成果物回収は回帰テストで確認しています。実生成smokeは64×64・1 step・LoRAなしで、画質評価を目的としません。
- 実Vast.ai／SSH／R2環境でのクラウド生成と、500枚連続の修正前後性能比較は未実施です。画像ごとにAPI送信しても同一のモデル入力はComfyUIのキャッシュ対象ですが、キャッシュ設定やメモリ不足で再ロード・転送が発生し得ます。
- 公開前に対象PRとmainのGitHub Actions CI成功を確認します。CIにはLinux回帰テスト・ビルド・画像メモリ検証を含みます。Windows専用更新テストはWindowsで確認します。
