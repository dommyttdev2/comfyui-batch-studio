## v0.81.1 — 非公開リポジトリの更新認証を修正

`update.bat` が非公開リポジトリの最新リリース取得時に HTTP 404 で停止する問題を修正しました。

### 修正内容

- `GH_TOKEN` / `GITHUB_TOKEN`、GitHub CLI のログイン、Git credential helper の順で既存の認証情報を取得し、リリース API とタグの fetch の両方で使用します。GitHub CLI は必須ではありません。
- タグ取得の認証は一時的なプロセス環境だけに設定し、成功・失敗どちらでも元の設定へ戻します。トークンをコマンド引数や Git 設定ファイルに含めません。
- API 取得失敗時には、認証・リポジトリへのアクセス権・正式リリース・ネットワークの確認を案内します。トークンを含み得る API 例外の詳細は表示しません。
- 認証の優先順位、API と fetch の認証、秘密情報の非出力、設定の復元に関する Windows 回帰テストを追加しました。

### 互換性と利用方法

`0.81.0` → `0.81.1`（PATCH）。公開済み更新機能の認証不具合を修正するため、プロジェクトの付番ルールに従い PATCH を上げます。データ移行は不要です。保存形式・Template / Manifest・Compiler・Remote Worker の番号は変更しません。

非公開リポジトリへのアクセス権を持つ既存の GitHub 認証を利用してください。GitHub CLI を使う場合は `gh auth login --hostname github.com` で事前にログインできます。アプリを終了して `update.bat` を実行し、更新後に `run.bat` で依存関係の更新・ビルド・起動を行ってください。

### 検証

- Windows 回帰テストで更新・再更新・変更保護・取得失敗と各認証経路を検証しました。
- 一時リポジトリで実際の非公開 GitHub リポジトリの API とタグ fetch を実行し、`v0.81.0` への切り替えに成功しました。
- 公開前に対象コミットの CI（整形・Lint、型チェック、全回帰テスト、ビルド、画像メモリ検証）の成功を必須とします。Windows 専用テストの Linux 上でのスキップを成功の根拠にはしません。
