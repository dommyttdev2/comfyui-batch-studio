## v0.80.0 — Windows 更新を最新正式リリースに統一

`update.bat` が GitHub の最新正式リリースを取得するようになりました。
開発ブランチの未リリース変更を取り込まず、公開されたタグのコミットへ切り替えます。

### 変更内容

- GitHub の `releases/latest` から正式リリースのタグを取得し、公式リポジトリから fetch して checkout します。Draft / Pre-release は対象外です。
- 未コミットの追跡ファイルの変更、未追跡ファイルとの衝突、リリース情報・タグの取得失敗では停止します。既存タグの強制上書きや変更の自動破棄は行いません。
- タグのコミットを直接参照する detached HEAD からも再更新できます。
- Windows PowerShell と一時 Git リポジトリによる回帰テスト、README の更新手順を追加しました。

### 付番と互換性

`0.79.0` → `0.80.0`（MINOR）。既存の更新コマンドに正式リリースの選択・取得と再更新の機能を追加するため、プロジェクトの付番ルールに従い MINOR を上げます。

開発段階の `0.x.y` のリリースです。更新先はブランチの先端から正式リリースのタグへ変更され、更新後は detached HEAD になります。開発作業を行う場合は作業ブランチへ切り替えてください。既存プロジェクト・設定・実行履歴の保存形式、Workflow Template / Manifest、Compiler、Remote Worker のバージョンは変更しません。データ移行は不要です。

Windows の更新には Git と Windows PowerShell が必要です。アプリを終了して `update.bat` を実行し、更新完了後は `run.bat` で依存関係の更新・ビルド・起動を行ってください。

### 検証

- Windows 更新回帰テスト: 正式リリースへの切り替え、再更新、未コミット変更・未追跡ファイルの保護、API 失敗・不正タグ・存在しないタグ・既存タグとの衝突を確認しました。
- ローカルの整形・Lint と型チェックは成功しました。Lint は既存の未使用変数に関する警告を含みます。
- Linux の全回帰テスト・ビルド・画像メモリ検証は、公開前に対象コミットの GitHub Actions CI 成功を必須とします。Windows 専用更新テストの Linux 上でのスキップを成功の根拠にはしません。
- 起動中のアプリが利用するローカルのビルド出力は更新していません。
