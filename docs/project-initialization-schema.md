# プロジェクト初期画面／Story Brief 設計

## 1. 方針

プロジェクト初期画面は、ユーザーが細かなストーリー設計を入力する画面にはしない。

ユーザーは「誰を対象に、どのような読者向けの作品を作りたいか」だけを入力する。人物の詳細、舞台、章構成、場面、衣装推移、カメラ設計などはGrok Webに提案させ、会話を通して `story.md` にまとめる。

初期入力は `project_brief.json` に保存し、Grokへ渡す最初の依頼文を組み立てる土台にする。

## 2. 既存 story.md の分析結果

既存の `story.md` 8本には、主に次の情報が含まれていた。

- タイトル、読者対象、登場人物、人物関係
- キャラクターの外見、性格、口調、衣装
- 舞台、時間帯、開始状態、終了状態
- トーン、感情、主導権、必須・禁止要素
- 章構成、場面展開、視覚クリップ
- カメラ、画角、光、表情、衣装状態の推移
- 目標画像枚数と章別ショット数

これらは完成した `story.md` には必要だが、すべてをユーザーの初期入力にする必要はない。以下のように責務を分ける。

| 情報 | 初期画面 | Grokとの会話・story.md |
| --- | --- | --- |
| プロジェクト名 | 入力する | 引き継ぐ |
| 版権キャラか | 入力する | 引き継ぐ |
| 版権キャラ名 | 条件付きで入力する | 原典として扱う |
| ターゲット読者の特徴 | 入力する | トーンと場面へ展開する |
| 成人・合意の前提 | 確認する | 全体制約として維持する |
| 大まかな要望 | 任意入力 | ストーリー案へ展開する |
| 外見・性格・原作設定 | 入力不要 | Grokに調査・整理させる |
| 舞台・人物関係 | 入力不要 | Grokに提案させる |
| 開始／終了状態 | 入力不要 | Grokに提案させる |
| 章・場面構成 | 入力不要 | Grokに提案させる |
| 視点・カメラ | 入力不要 | Grokに画像生成向けに設計させる |
| 衣装・状態推移 | 入力不要 | Grokに画像生成向けに設計させる |
| 禁止事項 | 任意入力 | Grokの提案後にも追加・修正できる |
| 画像枚数 | 初期値を使用、変更は任意 | 章・カット配分へ展開する |

## 3. 初期画面の必須項目

必須入力は次の5項目に限定する。

### 3.1 プロジェクト名

| 項目 | 値 |
| --- | --- |
| UI | 1行テキスト |
| 保存キー | `project.title` |
| 必須条件 | 1〜120文字 |
| 用途 | 画面表示、storyタイトル候補、プロジェクトフォルダ名の生成元 |

プロジェクトIDはユーザー入力を必須にしない。表示名から候補を自動生成し、保存時に重複しない連番を付与する。必要なら詳細設定で変更できる。

### 3.2 版権キャラである

| 項目 | 値 |
| --- | --- |
| UI | チェックボックス |
| 保存キー | `character.is_copyrighted` |
| 必須条件 | オン／オフを確定する |
| 用途 | キャラクター名の必須制御、Grokへの調査指示 |

初期画面では主対象キャラクター1人について入力する。複数キャラクターはGrokとの会話または後続編集で追加できる。

### 3.3 キャラクター名

| 項目 | 値 |
| --- | --- |
| UI | 1行テキスト |
| 保存キー | `character.name` |
| 必須条件 | 「版権キャラである」がオンの場合のみ必須 |
| 用途 | Grokがキャラクターを調査・整理するための検索原典 |

オリジナルキャラクターの場合は任意。空欄ならGrokに人物名や呼称を提案させる。

同名キャラクターの誤認を避けるため、「出典作品・シリーズ」は任意項目として隣に表示する。未入力でも開始できるが、複数作品に同名キャラクターが存在しうる場合は警告する。

### 3.4 ターゲット読者の特徴

| 項目 | 値 |
| --- | --- |
| UI | 複数行テキスト＋任意の候補チップ |
| 保存キー | `audience.traits` |
| 必須条件 | 1件以上、または10文字以上 |
| 用途 | Grokがトーン、関係性、重点場面、視覚表現を設計する基準 |

年齢・性別などの属性を細かく入力する欄ではなく、作品に求める体験を記述する。

入力例の観点：

- 好む関係性や主導権
- 求める感情や雰囲気
- 重視するキャラクターの魅力
- 重視する視覚要素やカメラ距離
- 避けたい物語の方向性

### 3.5 成人・合意の確認

| 項目 | 値 |
| --- | --- |
| UI | 確認チェックボックス |
| 保存キー | `constraints.adult_and_consent_confirmed` |
| 必須条件 | 対象となる人物が成人で、成人向け内容では合意を前提とすることを確認 |
| 用途 | story全体へ適用する固定制約 |

これはストーリーを細かく指定する入力ではなく、プロジェクト全体の前提確認として扱う。

## 4. 初期画面の任意項目

必須5項目の直下に、次の2項目だけを表示する。

### 4.1 大まかな要望

| 項目 | 値 |
| --- | --- |
| UI | 複数行テキスト |
| 保存キー | `request.overview` |
| 初期値 | 空欄 |
| 用途 | ユーザーが既に持っているテーマ、関係性、場所、場面などを自由に伝える |

空欄でもGrokへの依頼を開始できる。Grokには複数の大まかなストーリー案を提案させる。

### 4.2 出さないもの・避けたい方向性

| 項目 | 値 |
| --- | --- |
| UI | 複数行テキスト |
| 保存キー | `request.exclusions` |
| 初期値 | 空欄 |
| 用途 | キャラクター、衣装、時期、場所、構図、トーン等の除外条件 |

未入力でも開始できる。Grokの提案後、会話の中で追加できる。

## 5. 詳細設定へ移す項目

以下は初期画面に並べない。「詳細設定」を開いた場合だけ編集できる。すべて任意で、既定値を持つ。

| 項目 | 保存キー | 既定値 |
| --- | --- | --- |
| プロジェクトID | `project.id` | 表示名から自動生成＋連番 |
| 出典作品・シリーズ | `character.source_work` | 空欄 |
| story文書形式 | `story.format` | `narrative_clip` |
| 目標画像枚数 | `generation.target_image_count` | `500` |
| 想定モデル系 | `generation.model_family` | `Illustrious` |
| 章数 | `story.target_chapter_count` | Grokに提案させる |
| 参考ファイル | `grok.reference_files` | なし |

「出典作品・シリーズ」は版権キャラの識別精度を上げるため推奨するが、ユーザーが指定した必須項目にはしない。

## 6. 初期画面から外す項目

以前の案で必須としていた以下の項目は、初期画面から外す。

- キャラクターの外見アンカー、不変特徴、初期衣装
- キャラクターの性格、口調、物語上の役割
- 相手役、人物関係、主導権、第三者の扱い
- 舞台一覧、開始状態、終了状態
- 状態遷移、必須場面、章構成
- 視点、カメラ原則、視覚アンカー
- 衣装・外見の状態遷移
- クリップ記述粒度
- 優先順位や詳細な生成制約

これらはGrokが大まかなストーリー案と一緒に提案し、ユーザーが右ペインのチャットで調整する。

## 7. 初期画面のレイアウト

```text
┌─ 新しいプロジェクト ───────────────────────────┐
│ プロジェクト名 *                                │
│ [___________________________________________]   │
│                                                 │
│ キャラクター                                    │
│ [ ] 版権キャラである *                          │
│ キャラクター名（版権の場合は必須）              │
│ [___________________________________________]   │
│ 出典作品・シリーズ（任意）                      │
│ [___________________________________________]   │
│                                                 │
│ ターゲット読者の特徴 *                          │
│ [                                           ]   │
│ [                                           ]   │
│                                                 │
│ 大まかな要望（任意）                            │
│ [                                           ]   │
│                                                 │
│ 出さないもの・避けたい方向性（任意）            │
│ [                                           ]   │
│                                                 │
│ [ ] 登場人物は成人で、成人向け内容は合意を前提  │

```

「Grokで案を作る」を押すと、入力値を保存して右側のGrok Web用プロンプトを生成する。Grok Webへの貼り付けと送信はユーザーが行う。

## 8. project_brief.json

初期保存データは詳細なstoryスキーマではなく、次の小さな構造にする。

```json
{
  "schemaVersion": 1,
  "project": {
    "id": "15_demon-slayer_kocho-shinobu",
    "title": "胡蝶しのぶプロジェクト"
  },
  "character": {
    "is_copyrighted": true,
    "name": "胡蝶しのぶ",
    "source_work": "鬼滅の刃"
  },
  "audience": {
    "traits": "落ち着いた年上女性の主導、会話と表情、キャラクターらしい衣装を重視する読者"
  },
  "constraints": {
    "adult_and_consent_confirmed": true
  },
  "request": {
    "overview": "",
    "exclusions": ""
  },
  "story": {
    "format": "narrative_clip",
    "target_chapter_count": null
  },
  "generation": {
    "target_image_count": 500,
    "model_family": "Illustrious"
  },
  "grok": {
    "reference_files": []
  }
}
```

## 9. Grokへ最初に依頼する内容

Grokには完成版を一度で書かせるのではなく、最初にストーリー案と不足確認を依頼する。

```markdown
ComfyUIで大量の画像を生成するための `story.md` を作りたいです。
まず、以下の条件から大まかなストーリー案を提案してください。

## プロジェクト
- 名前: {{project.title}}
- 目標画像枚数: {{generation.target_image_count}}

## キャラクター
- 版権キャラ: {{character.is_copyrighted}}
- キャラクター名: {{character.name_or_unspecified}}
- 出典作品: {{character.source_work_or_unspecified}}

版権キャラの場合は、名前と出典を手がかりにWeb上の公開情報を調査し、
外見、性格、口調、代表的な衣装、原作上の時期を整理してください。
同名人物や設定の不確実性がある場合は、推測せず質問してください。

## ターゲット読者
{{audience.traits}}

## ユーザーの大まかな要望
{{request.overview_or_none}}

## 出さないもの・避けたい方向性
{{request.exclusions_or_none}}

## 固定前提
- 登場人物は成人として扱う。
- 成人向け内容を含む場合は合意を前提とする。
- ターゲット読者に合う関係性、舞台、開始状態、展開、終了状態を考える。
- 後でComfyUI用のprompt treeへ変換できるよう、画像化しやすい場面で構成する。

まだ完成版の `story.md` は書かず、次の順で返してください。
1. 調査・前提整理
2. 大まかなストーリー案を3案
3. 各案の画像化しやすさと特徴
4. 私が選ぶ必要がある点、または不足情報への質問
```

ユーザーがGrok上で案を選択・修正した後、2通目のプロンプトで完成版の `story.md` を依頼する。

## 10. Grokがstory.mdで補完する項目

最終的な `story.md` には、選択した文書形式に応じて次を含めるよう依頼する。

- タイトルと読者対象
- キャラクターの調査メモまたは設定
- 成人・合意・時期の前提
- 人物関係と物語の開始／終了状態
- 外見、性格、口調、衣装、不変の視覚特徴
- 共通の視覚クリップ指定
- 舞台、光、時間帯
- 章構成と各章の場面
- 各章の画像化ポイント
- 出さない人物、衣装、設定、表現
- 目標枚数へ展開するためのショット方針

これらはGrokの提案内容であり、ユーザーが初期画面ですべて入力する必要はない。

## 11. 検証条件

初期画面でエラーにするのは次の場合だけとする。

- プロジェクト名が空欄。
- 版権キャラのチェック状態が確定していない。
- 版権キャラがオンで、キャラクター名が空欄。
- ターゲット読者の特徴が空欄。
- 成人・合意の確認がされていない。

それ以外の不足はエラーにせず、Grokへの依頼文で「未指定」と明示する。
