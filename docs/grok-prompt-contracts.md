# Grok作業プロンプト契約

## 1. 目的

ComfyUI Batch Studio が Grok Web に渡すプロンプトの組み立て規則を定義する。

本書における「送信」は、アプリが作成した文字列をユーザーがクリップボードから Grok Web へ貼り付ける操作を指す。アプリは Grok Web の入力欄、添付、会話を自動操作しない。

## 2. 共通ルール

### 2.1 プロンプトの構成

すべての工程プロンプトは、次の順で構成する。

```text
1. タスクと成果物の宣言
2. 守るべき制約
3. アプリが抽出したプロジェクト文脈
4. ユーザーの追加入力
5. 添付すべきファイルの一覧
6. 返答フォーマット
```

ファイル本文が短い場合だけ本文を埋め込む。`models.json`、ComfyUI workflow JSON、巨大な `story.md` は、既定ではファイル添付を求め、プロンプト本文には要約とハッシュだけを載せる。

### 2.2 安全な受け渡し

- 添付候補はプロジェクトフォルダまたはテンプレートフォルダ内のファイルだけに限定する。
- `.env`、資格情報、R2設定、ブラウザデータ、実モデル本体（`.safetensors`）は添付候補に表示しない。
- Grokからの提案は下書きとして扱い、保存前にユーザーが確認する。
- Grokの利用規約およびコンテンツポリシーに反する指示・回避方法はプロンプトテンプレートに含めない。

### 2.3 成果物の返答形式

Grokには各工程の最終回答を、対象ファイルだけを含むコードブロックで返すよう依頼する。説明や変更理由はコードブロックの前に短く置く。アプリはコードブロックを候補として取り込み、ユーザーが選んだブロックだけをエディタに反映する。

| 成果物 | 要求するコードブロック | 保存前の基本検証 |
| --- | --- | --- |
| `story.md` | `markdown` | UTF-8、空でない |
| `prompt_tree.md` | `markdown` | UTF-8、モデル参照の警告検出 |
| `models.json` | `json` | JSON、`files[].name` |
| workflow | `json` | JSON、`nodes`・`links`・`groups` |

## 3. 変数の定義

| 変数 | 内容 | 情報源 |
| --- | --- | --- |
| `{{PROJECT_ID}}` | フォルダ名 | プロジェクト一覧 |
| `{{PROJECT_NAME}}` | 表示名 | 新規作成時の入力／メタデータ |
| `{{PROJECT_PATH}}` | 絶対パス | アプリ内部のみ。Grok本文には既定で含めない |
| `{{USER_BRIEF}}` | ユーザーの追加入力 | 左ペインのテキスト欄 |
| `{{STORY_SUMMARY}}` | story.mdの先頭・見出し構造・短い要約 | アプリ抽出 |
| `{{MODEL_SELECTION}}` | 固定モデルの短い一覧 | models.json |
| `{{CATALOG_CANDIDATES}}` | カタログ検索結果の要約 | model_catalog.json |
| `{{TREE_SUMMARY}}` | treeの章・枝・モデル参照の要約 | prompt_tree.md |
| `{{WORKFLOW_SUMMARY}}` | ノード種別・枝数・使用LoRAの要約 | workflow template |
| `{{ARTIFACT_NAME}}` | 今回の出力ファイル名 | 工程定義 |

## 4. Story 作成プロンプト

### 4.1 入力

- プロジェクト名
- 版権キャラかどうか
- キャラクター名（版権キャラの場合は必須）
- 出典作品（任意）
- ターゲット読者の特徴
- 成人・合意の確認
- 大まかな要望と除外事項（任意）
- 参考資料（必要な場合にユーザーが添付）

人物の外見・性格・口調、舞台、人物関係、章構成、カメラ、衣装推移は初期入力に要求しない。Grokとの会話で提案・調整する。

### 4.2 初回：ストーリー案を作るプロンプト

```markdown
ComfyUIで大量の画像を生成するための `story.md` を作りたいです。
まず、次の条件から大まかなストーリー案を提案してください。

## プロジェクト
- 名前: {{PROJECT_NAME}}
- 目標画像枚数: {{TARGET_IMAGE_COUNT}}

## キャラクター
- 版権キャラ: {{IS_COPYRIGHTED}}
- キャラクター名: {{CHARACTER_NAME_OR_UNSPECIFIED}}
- 出典作品: {{SOURCE_WORK_OR_UNSPECIFIED}}

版権キャラの場合は公開情報を調査し、外見、性格、口調、代表的な衣装、原作上の時期を整理してください。
同名人物や不確かな設定がある場合は推測で確定せず、質問してください。

## ターゲット読者
{{AUDIENCE_TRAITS}}

## 大まかな要望
{{REQUEST_OVERVIEW_OR_NONE}}

## 出さないもの・避けたい方向性
{{REQUEST_EXCLUSIONS_OR_NONE}}

## 固定前提
- 登場人物は成人として扱う。
- 成人向け内容を含む場合は合意を前提とする。
- ターゲット読者に合う関係性、舞台、開始状態、展開、終了状態を提案する。
- 後でComfyUI用のprompt treeへ変換できる、画像化しやすい場面構成にする。
- 他作品の文章を複製せず、新しいストーリー案として提案する。

まだ完成版の `story.md` は書かず、次の順で返してください。
1. 調査・前提整理
2. 大まかなストーリー案を3案
3. 各案の画像化しやすさと特徴
4. 私が選ぶ必要がある点、または不足情報への質問
```

### 4.3 二回目：story.mdを確定するプロンプト

```markdown
これまでの会話で選択・修正した案を基に、プロジェクト「{{PROJECT_NAME}}」の `story.md` を作成してください。

## 出力要件
- 確定したターゲット読者、キャラクター、物語案、除外事項を維持する。
- 後でComfyUI用のprompt treeへ変換できるよう、人物の視覚特徴、衣装、舞台、時間、章ごとの場面、画像化ポイントを明確にする。
- 未確認の版権設定を事実として追加しない。
- `{{STORY_FORMAT}}` の構造に従う。
- 目標画像枚数 `{{TARGET_IMAGE_COUNT}}` へ展開できる粒度を持たせる。

## 返答
最終案は `story.md` の本文だけを `markdown` コードブロックで返してください。
```

### 4.4 手動添付案内

- 参考画像、設定資料、既存のstoryを継続利用する場合はそのMarkdown。
- テンプレートを本文へ展開する必要がある場合は `stories-template.md`。
- 作品に関係しない過去プロジェクトのファイルは既定で添付しない。

## 5. Models 選定プロンプト

モデルの確定自体は左ペインのカタログ選択機能で行う。Grokには、候補の比較・必要な追加モデルの要件定義を依頼できるが、Grokの文章から直接 `models.json` を上書きしない。

### 5.1 入力

- `story.md` の要約
- Civitaiカタログの検索結果。各候補はモデル名、バージョン、トリガー、ファイル名、容量、URL、ベースモデルを含む。
- 既に固定済みのモデル一覧

### 5.2 コピー用テンプレート

```markdown
あなたはComfyUI用モデル選定のレビュアーです。

## タスク
以下のストーリーと候補カタログを基に、プロジェクトに必要なチェックポイントとLoRAの選定方針を提案してください。
提案は候補の事実情報と、ストーリー上の必要性を分けて記述してください。

## ストーリー要約
{{STORY_SUMMARY}}

## 現在固定済みのモデル
{{MODEL_SELECTION}}

## Civitaiカタログ候補
{{CATALOG_CANDIDATES}}

## 制約
- 候補にないモデルを必須とする場合は、用途・必要なベースモデル・想定トリガーだけを明記する。
- 存在しないファイル名やバージョンを推測で断定しない。
- 同時使用するLoRAの競合・ベースモデル不一致・過剰なスタックを警告する。

## 返答
「採用候補」「保留／不要」「不足モデル要件」「ワークフロー上の注意」の4節で返してください。
```

### 5.3 models.json の確定規則

- ユーザーが左ペインのカタログ候補を選択する。
- アプリが既存のCivitai Selection APIと互換の形式で `models.json` の候補を生成する。
- ユーザーが差分を確認し、明示保存する。
- `files` の実体候補から `.safetensors` 等を明示できるが、カタログ本来の情報は失わない。

## 6. Prompt Tree 作成プロンプト

### 6.1 入力

- 確定済み `story.md`
- 確定済み `models.json`
- `prompt_tree生成プロンプト.md`
- 任意の参考 `prompt_tree.md`（構造参照のみ）

### 6.2 コピー用テンプレート

```markdown
あなたは ComfyUI と {{BASE_MODEL_FAMILY}} 向けのプロンプトツリー設計者です。

## タスク
添付した `story.md` と固定済みのモデル一覧から、`prompt_tree.md` を作成してください。
場面を生成可能な枝へ分割し、各枝で必要なLoRA、トリガー、強度の目安、ポジティブ／ネガティブの方針、枚数、保存名を明記してください。

## 絶対制約
- `models.json` にある実ファイル名を優先して参照する。
- カタログにないモデルを必要とする場合は、既存モデルとして偽装せず「新規取得候補」として明記する。
- 同時使用LoRAは必要最小限にし、競合があり得る組み合わせを注記する。
- 参考treeは章立て・ツリー表現の参考に限り、内容を複製しない。
- 添付資料とサービスのポリシーを守る。

## 固定モデル一覧
{{MODEL_SELECTION}}

## story.md の要約
{{STORY_SUMMARY}}

## 参考treeの構造要約
{{REFERENCE_TREE_SUMMARY}}

## ユーザーの追加方針
{{USER_BRIEF}}

## 添付するファイル
- story.md
- models.json
{{OPTIONAL_TREE_ATTACHMENT}}

## 返答
最終案は `prompt_tree.md` の本文だけを `markdown` コードブロックで返してください。
```

## 7. Workflow 作成プロンプト

### 7.1 入力

- 確定済み `prompt_tree.md`
- `models.json`
- `workflows/LoRA Character Batch.json`
- `ワークフロー生成プロンプト.md`

### 7.2 コピー用テンプレート

```markdown
あなたは ComfyUI workflow JSON を編集する専門家です。

## タスク
添付のワークフロー雛形を基に、添付した `prompt_tree.md` と `models.json` に合う
`LoRA_{{PROJECT_ID}}.json` を作成してください。

## 雛形構造の維持
- 雛形のノード種別、接続構造、既存カスタムノードを変えない。
- 必要なLoRAパターン数だけ既存枝を設定する。未使用枝は空のLoRAスタック・空のMatrix・bypassとして残す。
- 各利用枝のMatrix行はファイル名付与を有効にする。
- モデル／LoRA名には `models.json` に存在する実ファイル名だけを設定する。
- JSON以外を最終コードブロックに混ぜない。

## prompt tree の要約
{{TREE_SUMMARY}}

## 固定モデル一覧
{{MODEL_SELECTION}}

## 雛形の構造要約
{{WORKFLOW_SUMMARY}}

## 添付するファイル
- prompt_tree.md
- models.json
- LoRA Character Batch.json

## 返答
最終案はワークフローJSONだけを `json` コードブロックで返してください。
```

### 7.3 アプリ側の取り込み

workflow JSONは大きくなりやすいため、アプリはコードブロック抽出後に以下を表示する。

1. JSON構文エラー。
2. 雛形とのノード種別・リンク構造の差分。
3. `AnimaLoraStack` のファイル名と `models.json` の差分。
4. `SceneMatrix` の `filename_enabled` が無効な行。
5. 未使用枝の状態。

エラーがある場合も、ユーザーは下書きとして保存できる。確定ファイルへの上書きは、エラー内容を確認したうえで明示的に実行する。

## 8. 添付ファイル作業リスト

左ペインは工程ごとに、ユーザーがGrokへ手動添付するファイルをチェックリスト表示する。

```text
[ ] 添付対象を確認
[ ] 「フォルダを開く」でExplorerを開く
[ ] Grok Webの + メニューからファイルを添付
[ ] 左ペインのプロンプトをコピーして貼り付け
[ ] 最終回答を左ペインへ貼り戻す
[ ] 検証し、確定保存する
```

アプリの「フォルダを開く」は添付を補助するだけであり、ファイル選択ダイアログやGrok Webのアップロード操作を代行しない。
